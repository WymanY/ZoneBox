# 更新分发约定

ZoneBox 的更新源沿用公开仓库 `WymanY/ZoneBox` 的 GitHub Releases。检查接口是
`https://api.github.com/repos/WymanY/ZoneBox/releases/latest`，不需要在客户端配置 GitHub 令牌。

## 应用内使用

首页布局面板在发现新版本时显示更新提示按钮，点击后进入「设置 → 通用」查看和下载。
提示会随下载状态更新，下载完成后提供安装包入口；没有可用更新时隐藏。
重启后仍保留已知新版的提示；若尚未缓存安装包信息，点击提示时会重新查询下载信息。
菜单栏也保留「检查更新」入口。

「设置 → 通用」中的检查频率提供四种选择，并在重启后保留：

| 频率 | 行为 |
| --- | --- |
| 每次启动 | 启动后检查一次，运行期间的唤醒、激活不重复触发。 |
| 每天（默认） | 距上次成功检查满 24 小时后检查。 |
| 每周 | 距上次成功检查满 7 天后检查。 |
| 仅手动 | 不自动检查，使用「立即检查」主动查询。 |

自动检查在启动约 8 秒后按需执行；每天、每周策略也会在应用持续运行、系统唤醒和应用激活时复查是否到期。
每天、每周模式在检查失败后至少间隔 15 分钟才允许再次自动请求；「每次启动」在每次重新启动时检查，同一次运行中不会重复检查。手动检查始终可用。
旧设置中开启自动检查会迁移为「每天」，关闭自动检查会迁移为「仅手动」。

发现新版本后，用户确认下载。界面显示进度，支持取消和失败重试。
安装包通过大小和 SHA-256 校验后，提供「在 Finder 中显示」和「打开安装包」操作。

菜单「更新可用 x.y.z」和设置里的蓝色「可更新至 x.y.z」都会直接开始下载，不再弹出确认框。
正式版且当前应用可写时，下载后继续校验 DMG 内的 ZoneBox.app（签名团队 A594W68DE5、bundle com.fancyzone.app、版本、架构），再由 helper 在本进程退出后替换并重启；不使用 sudo。
open 返回 0 只表示 Launch Services 接受了启动请求，不是新进程已稳定运行。成功替换后会在目标旁边留下隐藏的 zoneboxbackup 目录，不在启动当时删除，以便新副本立刻崩溃时还能手动找回上一份。
Debug 版（com.fancyzone.app.debug）仍可下载，但不会用正式版覆盖当前 Debug 应用，界面会说明请打开安装包另行安装。
只读、临时运行位置或签名不匹配时同样保留安装包，改为手动打开。

## 发布新版本

1. 在构建前同步 `project.yml` 中的 `MARKETING_VERSION` 和 `CURRENT_PROJECT_VERSION`，并重新生成 Xcode 工程。应用读取构建产物的 `CFBundleShortVersionString` 作为当前版本。
2. 使用递增的正式版本号作为 release tag，例如 `0.6.0` 或 `v0.6.0`。草稿和预发布版本不属于正式更新渠道。
3. 上传可供用户安装的 DMG，例如 `ZoneBox-0.6.0.dmg`。源码归档不能代替安装包。通用命名的 DMG 应包含所支持架构的应用；若按架构分别发布，文件名应明确包含 `arm64` 或 `x86_64`。
4. 确认 release 被 GitHub 标记为 Latest，安装包公开可下载，且 API 中的安装包大小与实际文件一致。保留 GitHub 为资源提供的 SHA-256 digest；发布 `SHA256SUMS` 也有助于人工校验。
5. 使用低于新版本的应用完成检查、下载、取消/重试和打开安装包的验收，再通知用户更新。

下载与安装分开处理：用户确认后下载，完成后由用户打开安装包安装。更新功能不会自行覆盖正在运行的应用。

用户点击更新入口后下载；正式可写副本在校验通过后由 helper 替换并重启。Debug 与不可自动替换的副本只下载，不覆盖当前应用。

## 发布前检查

```sh
gh api repos/WymanY/ZoneBox/releases/latest \
  --jq '{tag_name, draft, prerelease, assets: [.assets[] | {name, size, digest, browser_download_url}]}'
shasum -a 256 ZoneBox-<version>.dmg
```

当前源码构建版本为 `0.5.3`（build 8）。发布后 GitHub Latest 与安装包版本应与此一致。

GitHub API 和下载站点需要网络可达。离线、限流和资源删除属于可恢复失败，应通过应用内的手动检查或重试重新发起。

## 手动验收场景

- 当前版本低于最新正式版时，检查结果提供安装包下载入口；等于或高于正式版时，不提示降级。
- 切换四种检查频率后重启应用，选择仍然保留；「仅手动」不自动检查，但手动检查仍可使用。
- 「每次启动」在本次启动检查后，唤醒和激活不重复检查；每天、每周分别遵循所选间隔。
- 有新版本时首页显示可点击的提示按钮；点击后可直接进入更新设置，不影响布局选择。
- 下载中显示进度，取消后停止传输；重试能够重新下载。
- 断网、接口限流或资源不存在时显示可理解的失败信息，恢复网络后可以重试。
- 文件大小或 SHA-256 不匹配时，不将文件作为可安装的下载结果。
- 下载完成后可以在 Finder 中定位文件，并由用户打开安装包；取消或失败不会影响现有应用。
- 下载完成后退出并重新打开应用，已校验的安装包仍可定位和打开；关闭自动检查也不应隐藏本地下载结果。

接口说明：[GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)。
